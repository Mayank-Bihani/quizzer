Quizzer Design System · Artifact 1 of 5

Foundations

The token layer for all three Quizzer surfaces — student app, live quiz runner, admin console. Everything downstream (primitives, quiz run, results, admin) is built from exactly these tokens; the A/B/C picks below repoint alias variables only, so any mix of selections still composes into one system. Light UI only, but every value is a custom property so a dark theme can be layered later.

01Colour system

Neutrals are cool and slightly blue so they sit correctly on the ambient wash. Text never uses pure black. Semantic ramps carry only three steps each (50 / 500 / 700) because status is always drawn as tint + border + ink, never as a full-saturation fill.

Neutrals — --n-0 … --n-950

consumes--n-*--text-1/2/3--border-1/2

Accent — --accent-*

A single confident blue. Reserved for the primary action, the per-question timer fill, selection state and links. It is deliberately not one of the four section colours, so "the thing you can press" never reads as "the section you're in".

Semantic

Negative marking means red appears in real content (a −1 score, a wrong review answer). --danger-* is therefore muted rather than fire-engine, and destructive actions get their weight from copy and a confirm step, not from a louder red.

consumes--success-*--warning-*--danger-*--info-*--status-*

02Section identity 3 variants

Four identities: Verbal, Quant, Logical Reasoning, Overall (neutral). Requirement: they must stay separable after glass desaturates and lightens them, and they must not collide with the semantic ramps. Each family is shown three ways — solid, as a chip on heavy glass over a busy backdrop, and as a 3px section rule.

Recommendation: A. All three are warm-academic and all avoid the accent blue, so "section" never reads as "pressable" — they differ on depth: A mid-tone, B deep, C soft. Watch the LR hue in every family: tobacco/amber/mustard all sit in the same region as --warning-500, so the per-question urgency state must keep carrying a shape and text change, not just colour.

consumes--sec-verbal|quant|lr|overall--sec-*-tint--sec-*-ink--glass-*

03Ambient background system 3 variants

Glass only reads as glass over a non-flat backdrop, so the backdrop is a foundation token (--ambient), fixed to the viewport and painted behind every surface — never a per-screen decoration. All three variants keep luminance in a narrow band (L* 94–98) so body text passes contrast anywhere on the page.

TokenRoleValue

Math is rendered by KaTeX at runtime; --font-math is only the pre-hydration / fallback face, so a stem never reflows more than one line when KaTeX lands. Block math gets its own --sp-5 vertical rhythm and may scroll horizontally on its own axis — it must never widen the card.

06Spacing scale canonical · no variants

A 4px base with two deliberate half-steps (2px, 6px) for hairline-adjacent optical fixes. Component padding uses --sp-4…--sp-8; section rhythm uses --sp-9…--sp-12. Phone gutter 16px, desktop 24px. Touch targets never below --tap-min (44px); primary live-run actions use --tap-comfortable (52px).

07Radii scale canonical

Rule of nesting: an inner surface is exactly one step below its parent (--r-lg card → --r-md inner panel → --r-sm chip) so concentric corners never look wrong. --r-2xl is reserved for bottom sheets (top corners only). --r-pill for chips, badges and the room-code segments.

08Elevation scale canonical

Shadows are two-part (tight contact + wide ambient) and never tinted with the accent. On glass, elevation is carried mostly by the inset highlight ring (--glass-ring) — dropping a heavy shadow under a translucent panel makes it read as plastic. Levels map to: 1 = resting row, 2 = card, 3 = popover/sheet, 4 = modal.

09Motion tokens canonical

TokenValueUsed forPreview

Timers are the exception to everything: countdown fills use --ease-linear and are driven by real remaining time, never by a CSS animation that could drift. --ease-emphasis is the system's only overshoot and is spent on exactly one moment — the answer-lock confirmation.

Reduced motion: prefers-reduced-motion: reduce zeroes every duration and flattens --ease-emphasis. Timers keep their value-driven fill (it is information, not decoration) but stop pulsing; urgency then falls back to the digit-weight change and the "5s left" label. Question transitions become instant swaps. Ambient blobs never animate in either mode.

10Illustration style 3 variants

The same four objects — a stack of question cards, an hourglass, a completed card with a ribbon, a torn card — drawn three ways: empty (no quizzes yet), waiting (holding for the deadline), finished, error. Flat SVG files in assets/illustrations/, ≤ 2 KB each, drawn on a 160×120 box so they drop into cards at 96–180px. The room-full state reuses the "error" scene with different copy. Friendly, not childish — no faces anywhere — warmth comes from the objects, the paper palette and the slight rotation, not from eyes.

A — Cut paper

tradesLayered warm paper shapes, no outlines, no faces — objects (cards, hourglass, ribbon) rather than characters. Reads instantly at 64px and never turns childish.
useDefault. Matches the hairline/glass chrome and sits naturally on the parchment ambient.

B — Soft shade

tradesThe same objects rendered dimensionally — two-stop gradients, cast shadow, one highlight stroke. Most tactile; gradients can band on cheap panels and compete with the ambient mesh.
useBig single moments only: rank reveal, podium, first run.

C — Ink line

tradesWarm ink outline with hatching, drawn slightly off-square. Most human; the 2.6px stroke gets fragile below 72px and on 1× screens.
useIf the group should feel like a study group rather than a testing product.

Tone guard: illustrations never comment on performance. There is no sad mascot for a low score and no celebration for a high one — negative marking makes that cruel or smug. Celebration is reserved for completion, not results.

11Iconography canonical

substitutionNo icon set was supplied. The system standardises on Lucide (CDN) — 24×24 grid, 1.75px stroke, round caps — because its stroke weight matches the hairline chrome and it includes everything the three surfaces need (clock, timer, upload, shuffle, lock, trophy, users, chevrons). Icons are stroke-only; no filled duotone. Status icons are mandatory, never decorative: every status colour is paired with a glyph so the signal is not colour-only. Emoji are not used anywhere in the product UI.

12Focus ring on glass canonical

Tab through to see the live :focus-visible version.

Two rings, always: a 2px white spacer then a 2px accent ring (--focus-ring). On translucent surfaces the spacer becomes 95% white and the ring darkens to --accent-600 (--focus-ring-on-glass) — a mid-blue ring over a blurred blue lobe disappears otherwise. Rings sit outside the border box (box-shadow, not outline) so they never shift layout, and are never clipped by overflow: hidden parents — scroll containers get padding: 2px to make room.

15Open questions

  • Brand assets. No logo, wordmark, font files or icon set were supplied. Nothing has been invented: wherever a mark belongs, the system renders the word "Quizzer" in --font-ui at --fw-semibold. Send real files and I will swap them in.
  • Section naming vs colour. Assumed exactly three sections forever (Verbal / Quant / LR). If a fourth ever appears, family A has no obvious fourth hue left that survives glass — worth knowing now.
  • Negative marking display. Assumed marks-wrong is shown as a signed number (−1) in --danger-700 text, not as a red fill. Confirm.
  • Speed bonus units. Assumed the bonus is added to the score in the same unit as marks (so totals can be fractional, e.g. 38.5) rather than being a separate metric. This drives numeral width in every score component.
  • Grace window semantics. Assumed: answering within the grace window earns the full speed bonus and the bonus then decays to zero across the remaining seconds. Batch 3's timer variants depend on this reading.
  • Tie-break. Assumed total time is the only tie-break, shown as m:ss on the leaderboard row. Confirm before Batch 4.
  • Dark mode timing. Tokens are structured for it, but no dark values are defined. If dark is likely within a quarter, the glass recipe pick should lean B (solid-leaning inverts predictably; deep glass does not).
